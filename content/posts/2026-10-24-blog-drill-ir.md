> ⚠️ **이 글은 실제 사건이 아닌 가상 시나리오(모의 훈련)예요.** 'Neon Crow(네온 까마귀)'라는 공격 그룹은 존재하지 않는 가상의 그룹이고, 아래 IP·로그는 훈련을 위해 지어낸 예시예요. AETHERION은 실제로 해킹당하지 않았어요.

안녕하세요, AETHERION 팀이에요. 오늘 저녁 실제 접속 장애를 겪은 김에, "만약 공격이었다면 우리는 제대로 대응할 수 있었을까?"를 확인하려고 탁상 모의 훈련을 했어요.

## 훈련 시나리오 (가상)
가상의 그룹 '네온 까마귀'가 (1) 접속 키를 무작위로 대입하고, (2) 요청 헤더를 아주 천천히 보내 서버 연결을 묶어 두고(slowloris), (3) 우리 API 응답을 다른 사이트에 몰래 끼워 넣으려 한다고 가정했어요.

## 가상 로그 예시 (지어낸 데이터)
```
[가상] 21:40:01 POST /api/chat 401 ip=203.0.113.77 key=****
[가상] 21:40:01 POST /api/chat 401 ip=203.0.113.77 key=****
... (1분에 수백 회 반복)
[가상] 21:41:10 GET /health  연결 열림, 헤더 미완성 상태로 60초 이상 유지 × 200개
```
※ 203.0.113.0/24 는 문서 예시용으로 예약된 IP 대역이에요.

## 훈련에서 찾은 빈틈
- 틀린 접속 키를 무제한으로 시도할 수 있었어요.
- 헤더를 끝까지 보내지 않는 느린 연결을 오래 붙잡고 있었어요.
- API 응답에 보안 헤더(nosniff, 프레임 차단 등)가 없었어요.
- 장애가 나도 "감시 프로그램이 마지막으로 언제 정상 확인을 했는지" 밖에서 알 방법이 없었어요.

## 그래서 바꾼 것 (실제 적용)
- 같은 곳에서 틀린 키를 1분에 20번 넘게 보내면 그 1분 동안 429로 막아요. 맞는 키를 쓰는 사용자는 영향이 없어요.
- 헤더 15초, 요청 본문 120초, 유휴 연결 10초 제한을 걸어 느린 연결을 자동으로 끊어요(408).
- 모든 API 응답에 nosniff, X-Frame-Options DENY, CSP, Referrer-Policy, Permissions-Policy 헤더를 붙였어요.
- /health 에 자동 감시의 마지막 점검 결과와 경과 시간을 함께 보여 줘요.
